# Chapter 02 — RV32I instructions

[← Previous: RISC-V basics](01_riscv_basics.md) | [Home](../README.md) | [Next: Datapath](03_single_cycle_datapath.md) →

## What you will learn

You will recognize the six RV32I instruction formats and connect their fields to the decoder and immediate generator.

## Formats

All base instructions are 32 bits. The low seven bits are the opcode. Other fields have meanings that depend on the format.

```text
R: | funct7 |  rs2 | rs1 | funct3 | rd | opcode |
I: |       immediate[11:0]       | rs1 | funct3 | rd | opcode |
S: | imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode |
B: | imm[12] | imm[10:5] | rs2 | rs1 | funct3 | imm[4:1] | imm[11] | opcode |
U: |             immediate[31:12]             | rd | opcode |
J: | imm[20] | imm[10:1] | imm[11] | imm[19:12] | rd | opcode |
```

The immediate bits are not always stored next to one another. `immgen.v` rearranges them and sign-extends them to 32 bits. B- and J-type immediates have a low zero bit because instruction targets are aligned.

## Useful examples

| Instruction | Format | Main operation |
| --- | --- | --- |
| `add x3,x1,x2` | R | `x3 = x1 + x2` |
| `addi x1,x0,5` | I | `x1 = x0 + sign_extended(5)` |
| `lw x2,0(x5)` | I | `x2 = memory[x5 + offset]` |
| `sw x1,0(x5)` | S | `memory[x5 + offset] = x1` |
| `beq x1,x2,label` | B | branch if values are equal |
| `lui x5,0x10000` | U | `x5 = 0x10000000` |
| `jal x10,label` | J | save `PC+4`, then jump |
| `jalr x13,0(x12)` | I | save `PC+4`, then jump to `x12` |

Tutorial 1 covers the arithmetic/logical operations, `LW`/`SW`, conditional branches, `JAL`, `JALR`, `LUI`, and `AUIPC` already implemented in the upstream decoder. The decoder also contains byte/halfword load/store controls and simple system/fence visibility; those are not required by the first exercises.

## Control view

The important control decisions are easier to see as a table:

| Instruction | ALU second input | Register write | Memory read | Memory write | PC action | Writeback |
| --- | --- | --- | --- | --- | --- | --- |
| `ADD` | `rs2` | yes | no | no | `PC+4` | ALU |
| `ADDI` | immediate | yes | no | no | `PC+4` | ALU |
| `LW` | immediate | yes | yes | no | `PC+4` | memory |
| `SW` | immediate | no | no | yes | `PC+4` | none |
| `BEQ` | `rs2` | no | no | no | target if equal | none |
| `JAL` | immediate path | yes | no | no | target | `PC+4` |
| `LUI` | immediate | yes | no | no | `PC+4` | immediate |

In the source these decisions are the outputs of `ID.v`: `reg_write`, `mem_read`, `mem_write`, `branch`, `jal`, `jalr`, `alu_op`, `alu_rs2_imm`, and `wb_sel`.

## Try it

Use the assembler to inspect one encoding:

```bash
riscv64-unknown-elf-as -march=rv32i -mabi=ilp32 \
  -o /tmp/simple_add.o single_cycle/programs/simple_add.S
riscv64-unknown-elf-objdump -d /tmp/simple_add.o
```

The toolchain is optional. The repository includes a generated byte-wide `single_cycle/programs/program.hex` for the default run.

## Expected result

You should see three arithmetic instructions and a terminal `jal x0, done` in the disassembly. The testbench confirms the arithmetic result in `x3`.

## Checkpoint

For `addi x5, x3, 8`, identify `opcode`, `rs1`, `rd`, `funct3`, and the 12-bit immediate in the instruction word. Then explain why `lw` uses the I format while `sw` uses the S format: loads need an `rd`, while stores need an `rs2`.
